## ⚡ Быстрый старт в 1 строку

Установка или обновление движка с автоматическим наложением всех 37 готовых модов в один шаг:

```bash
curl -sSL https://raw.githubusercontent.com/steklyashka33/HermesModsEngine/main/install.sh | bash
```

### 🔄 Обновление в 1 команду
Поддерживайте движок, системные моды и кэши в актуальном состоянии одной командой без простоя:
```bash
python3 ~/.hermes/mods/runner.py update
```
* **Синхронизация Git:** Безопасно загружает свежие обновления и исправления из репозитория.
* **Защита пользовательских модов:** Кастомные моды в `custom/` и секреты в `~/.hermes/secrets.yaml` сохраняются и гарантированно не затираются.
* **Предпусковая AST-проверка:** Симулирует наложение всех таргетов в памяти до записи на диск.
* **Zero Downtime:** Транзакционно применяет патчи к коду ядра без перезапуска системных служб или шлюза (`hermes-gateway`).
* **Доступные флаги:** `--check` (проверка наличия обновлений), `--dry-run` (симуляция обновления в памяти), `--no-apply` (загрузка без патчинга ядра), `--force` (жесткий сброс к origin/main).

### 🛠️ Ручная установка (2 команды)
```bash
git clone https://github.com/steklyashka33/HermesModsEngine.git ~/.hermes/mods
python3 ~/.hermes/mods/runner.py apply
```

> **Гарантия Zero-Downtime:** Процесс установки и наложения патчей никогда не перезапускает системные службы или шлюз (`hermes-gateway`). Все кэши инвалидируются и обновляются ядром на лету без прерывания сессий.

## 💡 Почему HermesModsEngine?

Кастомизация крупных агентных платформ неизбежно загоняет команды в **ловушку хард-форков**:

```text
               ЛОВУШКА ХАРД-ФОРКА                         HERMES MODS ENGINE
  ┌─────────────────────────────────────┐       ┌─────────────────────────────────────┐
  │ Апстрим Hermes выпускает обновления │       │ Апстрим Hermes выпускает обновления │
  └──────────────────┬──────────────────┘       └──────────────────┬──────────────────┘
                     │                                             │ hermes update
                     ▼                                             ▼
  ┌─────────────────────────────────────┐       ┌─────────────────────────────────────┐
  │ Конфликты слияния и сломанный код   │       │ Чистый апстрим ядра обновлен        │
  └──────────────────┬──────────────────┘       └──────────────────┬──────────────────┘
                     │ Недели отладки                              │ python3 runner.py apply
                     ▼                                             ▼
  ┌─────────────────────────────────────┐       ┌─────────────────────────────────────┐
  │ Отказ от обновлений или ре-форк     │       │ 37 модов транзакционно наложены     │
  │ (Устаревший, хрупкий монолит)       │       │ (AST проверен до диска, 0 ошибок)   │
  └─────────────────────────────────────┘       └─────────────────────────────────────┘
```

**HermesModsEngine** решает проблему через **декларативный оверлей поверх ядра**:
- **Хирургические декларативные патчи:** Каждая правка оформляется как замена целевого блока с уникальным окружающим контекстом.
- **Предпусковой статический AST-анализ:** Синтаксис Python проверяется через `ast.parse()` *до* записи изменений на диск. Невалидный код отсекается до применения.
- **Дельта-снапшоты и Watchdog шлюза:** Побайтовые снимки файлов ядра с SHA-256 гарантируют мгновенный откат при любых ошибках или при падении шлюза в 30-секундном окне наблюдения.
- **Изоляция через плоские JSON-кэши:** Ядро Hermes Agent общается с экосистемой модов строго через JSON-кэши по mtime, полностью исключая прямые импорты кода движка.

## 🌟 Ключевые возможности и стандарты

| Архитектурный базис | Принцип работы и преимущества |
|---|---|
| **🛡️ Нулевой простой (Zero Downtime)** | Ядро Hermes никогда не импортирует код `.engine/` или `runner.py`. Обмен данными идет строго через JSON-кэши (`.commands_cache.json`, `.locales_cache.json`, `.mcp_cache.json`). Ядро сбрасывает внутренние кэши по изменению `mtime` файла без перезагрузки процессов шлюза. |
| **⚡ Двухпроходное транзакционное наложение** | Патчи симулируются в памяти и проверяются парсером `ast.parse()` до изменения диска. Если блок не совпадает ровно 1 раз (0 совпадений или неоднозначность >1), транзакция мгновенно отменяется без побочных эффектов. |
| **📸 Дельта-снапшотирование ядра** | Модуль `snapshot_manager.py` вычисляет SHA-256 хэши затрагиваемых файлов и сохраняет их точную копию перед каждым запуском `apply`. Откат к предыдущему валидному состоянию доступен командой `python3 runner.py snapshot restore`. |
| **🐕 Сторожевой таймер шлюза (Watchdog)** | При наложении с флагом `--watchdog` модуль `watchdog.py` контролирует `hermes-gateway.service` в течение 30 секунд. При циклическом перезапуске или падении шлюза активируется автоматический откат к исходному снапшоту. |
| **🔌 Аварийный размыкатель (Circuit Breaker)** | Модуль `circuit_breaker.py` изолирует сбойные модули. Если мод систематически падает с ошибками в рантайме, его состояние переводится в `OPEN`, а патчи снимаются из ядра без падения самого агента. |
| **🌐 8 языков локализации (Mod Overlay)** | Слой колоцированной локализации наивысшего приоритета. Поддерживает русский (`ru`), английский (`en`), испанский (`es`), немецкий (`de`), французский (`fr`), китайский (`zh`), арабский (`ar`), португальский (`pt`) и любые коды BCP-47. |
| **🧩 Универсальный редуктор секций** | Strict Layout предотвращает монолитные файлы таргетов >50 КБ. Абстрактный редуктор движка объединяет компактные файлы `targets/*.yaml` в единый упорядоченный список наложения. |
| **🏎️ Спекулятивная параллельная гонка** | Паттерн для тяжелых API (STT/TTS). Облачный и локальный воркеры стартуют одновременно; первый вернувший результат объявляется победителем, а проигравший воркер **мгновенно отменяется**, освобождая ресурсы. |
| **🔒 Защита секретов маской POSIX 0600** | Чувствительные данные (`sensitive: true`) изолируются строго в `~/.hermes/secrets.yaml` с правами доступа `0600`. Публичные параметры хранятся в `config.yaml`. Секреты маскируются в терминале. |
| **📦 Переносимый чистый экспорт модов** | Команды `runner.py export` / `import` собирают архивы модов без служебных директорий `.git`, кэшей и ключей с защитой от TarBomb и Path Traversal. |

## 📋 Справочник по CLI (`runner.py`)

Управление экосистемой осуществляется через CLI-раннер:

```bash
# === Синхронизация и обновление из Git ===
python3 runner.py update                 # Атомарное обновление Git + симуляция + наложение
python3 runner.py update --check         # Проверка доступности обновлений без применения
python3 runner.py update --dry-run       # Симуляция обновления в памяти без изменения диска
python3 runner.py update --no-apply      # Загрузка изменений репозитория без наложения на ядро

# === Наложение и жизненный цикл ===
python3 runner.py apply                  # Наложить все моды в топологическом порядке DAG
python3 runner.py apply <mod_id>         # Наложить конкретный мод с его зависимостями
python3 runner.py apply --watchdog       # Наложить с 30-секундным контролем стабильности шлюза
python3 runner.py verify [mod_id]        # Проверить наложение в памяти без изменения файлов
python3 runner.py unpatch [mod_id]       # Мягкий откат: снимает кастомные моды, сохраняя ядро
python3 runner.py purge --confirm        # Полный снос всех модов до чистейшего ванильного ядра

# === Диагностика и аудит ===
python3 runner.py status                 # Информационный дашборд здоровья рантайма
python3 runner.py doctor                 # Комплексный аудит (Python, права, DAG, блокировки)
python3 runner.py diff [mod_id]          # Просмотр цветного диффа между ядром и модами
python3 runner.py logs <mod_id> -n 50    # Просмотр последних строк логов journalctl по моду

# === Инспекция и каталог ===
python3 runner.py list                   # Список всех модов со статусами и версиями
python3 runner.py list --format json     # Машиночитаемый формат для AI-агентов
python3 runner.py info <mod_id>          # Детальная карточка мода (таргеты, конфиг, команды)
python3 runner.py info <mod_id> --lang ru # Просмотр карточки на русском языке
python3 runner.py commands [--json]      # Сводная таблица зарегистрированных слэш-команд

# === Конфигурация и секреты ===
python3 runner.py config <mod_id>        # Просмотр параметров (секреты маскируются)
python3 runner.py config <mod_id> --set key=value          # Запись публичной опции в config.yaml
python3 runner.py config <mod_id> --set-secret key=value   # Запись секрета в secrets.yaml (0600)
python3 runner.py config <mod_id> --populate               # Заполнение дефолтных значений

# === Снапшоты и аварийная защита ===
python3 runner.py snapshot list          # Список доступных дельта-снапшотов ядра
python3 runner.py snapshot restore       # Мгновенный откат ядра к предыдущему снапшоту
python3 runner.py circuit-breaker status # Просмотр статусов изоляции сбоев (CLOSED/OPEN)
python3 runner.py circuit-breaker trip <mod_id> --reason "Сбой"   # Принудительная изоляция мода
python3 runner.py circuit-breaker reset <mod_id>                  # Сброс изоляции и включение

# === Разработка и дистрибуция ===
python3 runner.py create <mod_id> --type folder  # Скаффолдинг нового папочного мода
python3 runner.py validate --strict-layout       # Валидация синтаксиса AST и раскладки файлов
python3 runner.py test [mod_id] --no-cache       # Запуск тестов мода
python3 runner.py export <mod_id> --out mod.tar.gz --no-secrets  # Упаковка переносимого архива
python3 runner.py import mod.tar.gz              # Безопасная распаковка стороннего мода
```

## 🛠️ Создание нового мода в 3 шага

Используйте встроенный скаффолдер для генерации каркаса по стандарту Strict Layout:

```bash
# 1. Генерация шаблона
python3 ~/.hermes/mods/runner.py create my-feature --type folder

# 2. Валидация AST и схемы
python3 ~/.hermes/mods/runner.py validate my-feature --strict-layout

# 3. Наложение под наблюдением watchdog
python3 ~/.hermes/mods/runner.py apply my-feature --watchdog
```

Полные стандарты манифестов и схемы приведены в **[SPECIFICATION.md](SPECIFICATION.md)**.

## 🤖 Руководство для AI-агентов

Автономные AI-агенты разработки (Claude Code, OpenAI Codex, Cursor, Hermes Agent) могут проектировать, тестировать и патчить систему полностью автономно.

Официальное нормативное руководство: **[AI Agents Developer Guide](docs/ai-agents-guide.md)**.

Ключевые правила для агентов:
- **Запрет импортов движка:** Никогда не добавлять `import engine` в ядро Hermes.
- **Декомпозиция targets:** Использовать файлы `targets/*.yaml` для защиты от монолитов >50 КБ.
- **English-by-Default:** Базовые тексты — на английском, переводы — колоцированно в `i18n/*.yaml`.
- **Строгий запрет рестартов:** Категорически запрещено выполнять `systemctl restart hermes-gateway`.
- **Автономное самоисцеление:** Использовать `runner.py status --format json`, `verify`, `doctor` и `snapshot restore` для устранения инцидентов без человека.

## 🧪 Тестирование и надежность

Экосистема снабжена автоматизированным набором из **277 проходящих тестов**:

```bash
# Запуск полного набора тестов:
pytest ~/.hermes/mods/tests -q

# Запуск с остановкой на первой ошибке:
python3 ~/.hermes/mods/runner.py test -x --no-cache
```

Покрытие тестами охватывает:
- Проверку схем манифестов и поиск циклов в графе DAG (алгоритмы Кана и Тарьяна).
- Работу универсального редуктора секций и Strict Layout валидатора.
- Дельта-снапшоты ядра, побайтовую верификацию SHA-256 и откат.
- Слияние колоцированной локализации на 8 языков с синхронизацией через `FileLock`.
- Работу автомата состояний Circuit Breaker и счетчиков инцидентов.
- Безопасную очистку секретов при экспорте архивов.
